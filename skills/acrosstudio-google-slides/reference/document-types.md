# Google スライドの資料タイプと戦略分析の接続

対応する出力は **提案書・打合せ資料・費用試算・ROI 試算の Google スライド**です。分析は既存の 13 個の `strat-*` スキルを使い、資料化はこのスキルを使います。別の Google スライドテンプレートも、元の PPTX スキルの QM へのインストールも不要です。

## 共通の入力と実行

同梱の `examples/proposal.json`、`meeting.json`、`cost.json`、`roi.json` が実行できる入力例です。例の名称・数値は架空の検証データであり、実案件へ流用しません。確認済みの内容へ置き換えます。

共通項目は `type`、`title`、`subtitle`、`versionDate`、`copyrightYear` です。資料タイプに応じて次の入力を用意します。

| type | 入力 | 出力 |
| --- | --- | --- |
| `proposal` | `pages`: 各ページの `title`、`lead`、1〜3 個の `cards`（`title` と `lines`） | 原本デザインの表紙＋提案内容・費用・進め方などの本文 |
| `meeting` | `pages`: 議題・論点・選択肢・決定事項・担当者と期限を同じカード形式で整理 | 表紙＋打合せ資料・議事録・論点整理 |
| `cost` | `currency: "JPY"`、`basis`、`plans`: 構成ごとの `name`、`years`、`oneTimeCosts`、`monthlyCosts` | 初期/月額の全内訳＋初期合計・月額・年額・期間総費用 |
| `roi` | `currency: "JPY"`、`basis`、`plans`: テーマごとの `name`、`initialInvestment`、`annualOperatingCost`、`annualBenefit`、`years` | 前提＋年間/累計ネット効果・期間純利益・ROI・回収期間・期間総費用 |

費用・ROI にも同じ `pages` 形式で補足ページを追加できます。`basis` は本文に置く短い前提サマリーとし、戦略分析の長い前提・出典・リスク・確認事項は補足カードへ分けて残します。確認事項を 60 文字のリード文へ押し込んだり、消したりしません。ROI には計算定義のページも自動で付きます。

`oneTimeCosts` と `monthlyCosts` はそれぞれ `{ "name": "項目", "amount": 10000 }` の配列です。`[]` は費用なしと確認済みの場合だけ使います。不明な金額を 0 に置き換えません。`basis` に、確認済みか仮定か、台数・人数・利用量・税の扱い・含めない費用を明記します。

スキルの読み取りで返された絶対パスを `SKILL_DIR` とします。QM の `.packs/` ではなく、`acrosstudio-google-slides/` 本体のディレクトリです。`scripts/` と `examples/` はこの配下にあります。

QM では、書き込み承認と保存先確認の後、既存の接続済み Google トークンを使う次のコマンドで作成できます。認証情報を引数に渡しません。

```bash
node "$SKILL_DIR/scripts/create-deck.mjs" content.json DESTINATION_FOLDER_ID
```

マイドライブ直下への保存が明示的に承認された場合だけ、保存先を `root` とします。スクリプトは入力をネットワーク操作前に検証し、新規資料の作成 → メタデータ取得 → revision 条件付き描画を実行して、資料 ID・リンク・ページ数を返します。共有権限は変更しません。API 失敗時は非ゼロで終了し、再試行前に確認すべき作成済み ID を報告します。取得・描画の失敗で作成を無条件に再送しません。

他の環境の既存 Google ツールを使う場合や、描画リクエストを確認する場合は、空資料の作成・取得の後に共通ビルダーを使います。

```bash
node "$SKILL_DIR/scripts/build-deck.mjs" content.json presentation.json > updates.json
```

`presentation.json` は、作成したばかりの資料を Slides API で **フィールドを省略せず** GET した応答です。`pageSize`・`revisionId`・`slides[].pageElements` を含めます。ビルダーは、新規の空資料（Google が最初に作る未入力のタイトル・サブタイトル枠を含む）だけを受け付け、文字や画像のある既存資料を上書きしません。

終了コード 0 の場合だけ `updates.json` を `presentations/PRESENTATION_ID:batchUpdate` に送信します。低レベルのリクエスト JSON を書き直さず、同梱ビルダーを使います。原本の黒白ロゴ・表紙背景・座標・フォント比率を適用し、正しい `createImage.url`、`elementProperties.pageObjectId`、5 文字以上の新規 object ID、`textRange.type: "ALL"` と revision 条件を生成します。トークンをこの JSON やスクリプトに書き込みません。

既存資料の部分修正は `reference/qm-api.md` の手順で行い、新規作成ビルダーに既存資料を渡しません。

## 提案書

`proposal_full.js` / `proposal_section.js` と原本の文書タイプ別ガイドを土台に、背景・課題 → 方向性 → 提案詳細 → 費用・対象範囲 → 進め方を整理します。不要な章は省略できます。各ページに結論となるリード文を置き、原本にあるカード構成へ内容をまとめます。

必要な分析だけを `strat-situation-assessment`、`strat-strategic-options`、`strat-narrative`、`strat-decision-memo` などへ依頼し、出力をページに反映します。分析の `## 要点` / `## 確認事項` を引き継ぎ、出典や未確定事項を消しません。費用・ROI ページを含む提案では、同じ入力を下記の計算ヘルパーに渡した結果を使い、分析と資料で数字を二重に作りません。

## 打合せ資料

`meeting_doc.js` と原本の議事録・検討資料・論点整理の構成を使います。目的・議題、確認した事実、選択肢、決定事項、未決事項、次の行動（担当者・期限）を区別します。分からない担当者や期限を作りません。

選択肢の整理には `strat-strategic-options`、決裁資料には `strat-decision-memo`、関係者調整には `strat-stakeholder-alignment` を必要に応じて使います。単なる議事録へ不要な分析チェーンを追加しません。

## 費用試算

`cost_estimate.js` の考え方を引き継ぎ、初期費用と継続費用を分離します。クラウド・オンプレなどは別の `plans` として比較できます。全項目を集計し、内訳が多い場合はページを分けて **全項目を残します**。

計算は `scripts/financials.mjs` の `calculateCosts()` を使います。

- 初期費用 = `oneTimeCosts` の合計
- 月額運用費 = `monthlyCosts` の合計
- 年額運用費 = 月額運用費 × 12
- 期間総費用 = 初期費用 + 年額運用費 × 評価年数

金額は非負の整数円、評価期間は正の整数年です。税・割引・インフレ・為替換算を自動推定しません。円以外や月単位の評価が必要なら、その要件を確認してから対応範囲を判断します。レンジの場合は下限・上限の確認済み入力を別 plan にし、勝手な中央値を使いません。

## ROI 試算

元の `roi_excel.py` の計算定義を使います。元ファイルは Excel の整形例なので、Slides 作成のためにそのスクリプトを実行する必要はありません。確認済みの入力を `calculateRoi()` へ渡し、スライドに前提・計算結果・計算方法を表示します。

- 年間ネット効果 = 年間効果 − 年額運用費
- 累計ネット効果 = 年間ネット効果 × 評価年数
- 期間純利益 = 累計ネット効果 − 初期投資
- ROI（%）= 期間純利益 ÷ 初期投資 × 100
- 回収期間（年）= 初期投資 ÷ 年間ネット効果
- 期間総費用 = 初期投資 + 年額運用費 × 評価年数

初期投資 0 の ROI は `算出不可`、年間ネット効果が 0 以下の回収期間は `効果不足` と表示します。負の効果・ROI を隠したり、費用を二度引いたりしません。費用スライドと ROI スライドの初期投資・年額運用費を一致させます。

`strat-business-case` と連携して効果の根拠・前提・リスクを整理します。年間効果が不明なら分析スキルにも推測で埋めさせず、確認を待つか未確定の資料として扱います。ROI 定義が既存の分析と異なる場合は計算を進める前に定義を確認します。

出力は編集可能な **Google スライド上の前提・数値・図表**です。Excel の入力セル・数式による自動再計算は Slides の機能ではありません。再試算時は確認した入力で計算・資料更新をやり直します。

## 完成条件

テンプレートを求めず、新規の Google スライドに原本の実物アセットで描画されていること。全ページを画像で見て、配色・フォント・ロゴ・余白・はみ出しを確認します。提案書・会議資料は内容と未決事項、費用・ROI は内訳・前提・合計・計算式も検算します。計算・API 成功だけで見た目を確認済みとしません。
